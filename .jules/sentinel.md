## 2024-11-11 - SQL Injection in Database Rollback Script
**Vulnerability:** A SQL injection vulnerability existed in `automation/python/rollback.py` when attempting to execute `DROP ROLE` via `psql`. The `config.db_user` attribute, which could contain arbitrary strings depending on config injection, was not properly escaped when constructing the command `f'DROP ROLE IF EXISTS "{config.db_user}";'`.
**Learning:** Proper string formatting is insufficient to mitigate SQL injection when dropping roles, databases, or creating users. We must replace double quotes (e.g., `""`) since we enclose the user string with double quotes for creating a SQL identifier safely. A similar fix was discovered and addressed in `automation/python/setup_steps.py` and `automation/ops/reset_ksc_databases.py`.
**Prevention:** Always escape dynamic values appropriately before injecting them directly into raw SQL commands executed by wrappers such as `psql -c` or via Python's `subprocess`, primarily by properly escaping SQL identifiers by replacing double quotes with two double quotes (e.g., `.replace('"', '""')`).
